# Worker and goal contracts

A worker spec is a JSON object. Its `task` describes a bounded outcome. Required executable bounds are `funding` (`byok` or `managed`), `profile` (`economical-v1`, `visual-v1`, `reviewer-v1`), integer `maxModelCalls`, `maxToolCalls`, `maxOutputTokens`, `maxRetailMicrousd`, `maxSeconds`, and `delegationLimit: 0`.

`references` contains project-relative files; `referenceDigests` maps every reference to its lowercase SHA-256. The worker can read only those references and its own immutable artifact namespace. `tools` selects from `project_read`, `project_image`, `artifact_write`, `render_ffmpeg`, `analyze`, `analysis_status`; `submit_result` is always available and counts toward the tool bound. No generic shell/process/network/purchase capability is available. A tool mutation has a durable ID and intent; exact retry returns the original receipt. Render inputs retain source identities and cannot import unapproved source paths.

`outputSchema` is JSON Schema 2020-12 for the structured `submit_result` object. `artifacts` is a list of `{path, kind, sha256?, schema?}` contracts, where `path` is relative to the project, and `kind` is `file`, `json`, `composition`, `render`, or `review`. Worker artifacts live under `workers/TASK_ID/artifacts/`; its result is `workers/TASK_ID/result.json`. The caller replaces `TASK_ID` with the exact CLI handle before admission. A review report has `sourceSha256` and `findings`; source linkage is checked against verified rendered bytes when both kinds are required. File existence does not imply editorial signoff.

For example, an economical structured metadata review may allow three model calls, five tool calls, 1024 output tokens, 60 seconds and `maxRetailMicrousd: 200000` (USD 0.20). This is a specification example, not permission to spend. Quote current exact model/provider prices and stay inside the parent's actual authorized allowance before starting. A visual or stronger reviewer profile has a different reservation cost and cannot replace the economical model silently.

A goal spec requires:

- `objective` and nonempty `acceptance` criteria.
- `steps`: ordered complete bounded worker specs.
- Integer overall `maxRetailMicrousd`, at least the sum of child maximum allowances; the local store reserves each child once and retains unknown settlements.
- Future Unix `deadlineUnix`; the detached process does not imply work during sleep/offline periods.
- `completionArtifacts` containing at least `composition`, `render` and `review` contracts. Use deterministic child artifact paths `workers/GOAL_ID-step-1/artifacts/...` and subsequent step handles. Long IDs use a stable hash; obtain the actual child handle from goal status rather than assuming the readable form.

States distinguish active, waiting, paused, blocked, failed, canceled, budget-limited and complete. Inspect `revision` before mutation. Pause then edit only before child steps have been admitted. Once scope has durable child operations, preserve them and use an explicit successor goal for changed scope. Resume reconstructs the same records and refuses indeterminate original operations. Completed replay is read-only.

Code/artifact qualification is recorded in the release evidence. Both named parent harnesses, both real funding paths, actual costs and a real multistep editorial crash/retry journey remain required before full companion launch acceptance. A local fixture provider, schema pass or prompt acknowledgement supplies none of those missing commercial/editorial proofs.


`maxNoProgressCalls` optionally bounds calls since the latest distinct artifact SHA (default3, range1–20). Reads, prose and repeated identical bytes do not reset it. A later step may specify `derivedReferences:[{"step":0,"path":"workers/GOAL_ID-step-1/artifacts/composition.json"}]`; each binding must name an earlier step's declared artifact. The supervisor waits for its completed checkpoint, verifies the actual SHA and adds it to the child's references/digests without changing the original goal specification.

Paid delegation requires `analysisPermissions:[{"operationId":"EXACT_NATIVE_ID","service":"video","source":"media/clip.mp4","sourceSha256":"SHA256","maxRetailMicrousd":100000,"options":{}}]`. Source must also be a parent reference with that digest. Services are `video`, `faces`, `speakers`; optional `maxDownloadBytes` is bounded to128MiB. `analyze` arguments must exactly match the permitted operation/service/source/SHA/cap. `analysis_status` addresses the same operation and can request a verified bounded artifact download. Options cannot override funding, provider, model, URL or job identity. These are illustrative values and confer no spending authority.

One server parent allowance covers the goal's inference and permitted native analyses. The local analysis hold is committed before upload/admission. A native capability must advertise `fundingAllowance:{"field":"fundingAllowanceId","sharedGoal":true}`. Final settlement must identify the original parent reservation and exact retail micro-USD before releasing the local cap; missing cost proof keeps the hold and blocks completion. Observer timeout never replaces the original native job. Cancellation targets that original handle while accepted usage still settles.

Managed transport is durable request admission and polling, with completed OpenAI JSON buffered as local SSE for Pi. It is not upstream token streaming. Profiles pin model, provider route, dated provider endpoint name, current pricing digest/expiry and disclosed2x retail ceiling. Credential rotation for the same customer account/mode does not change original operation ownership.

A committed `submit_result` can be recovered through explicit `worker recover` after lease expiry only if its exact bytes/contracts validate and every financial/tool operation settled. The original RPC outcome remains recorded as unknown; no model call is replayed. Bundle snapshots preserve IDs/caps/holds/checkpoints, exclude credentials and Pi chat/session files, and restore live records paused with a newer fence. They never resume work implicitly.

The optional integer `platformBudgetMicros` explicitly allocates actual infrastructure inside the same retail ceiling (default0). The server reserves provider budget as `maxRetailMicros//2-platformBudgetMicros`; infrastructure is never relabeled as OpenRouter usage. A goal owns this split once; native permissions keep exact total caps while the service freezes its own provider/platform estimates. Nonzero child allocations must fit the parent allocation. A new allocation requires explicit scope/budget authority and never raises the original cap automatically.

Native execution may be terminal before platform costs are financially settled. Only the protected native receipt's four true fields (`terminalExecutionProven`, `providerChildrenSettled`, `platformCensusKnown`, `readyForParentSettlement`) permit verified committed artifacts to form an execution checkpoint while worker/child retail caps stay held. Declared later steps can consume those exact SHA-bound bytes. After all steps are ready, close the one original parent, then observe the original native jobs and complete workers/goals only after authoritative retail acknowledgement. A held parent close remains closing with original work/holds; resume performs no replacement inference. Standalone workers use the same close/reconcile rule.
